# 5.4.2 Known gaps

Topics:
- 5.4.2.1 Missing features
- 5.4.2.2 Documentation gaps

Moved from the repository's README on 2026-10-03 (global Rule 7.1: the README holds no design).

## 5.4.2.1 Missing features

- DNS-over-TLS (`:853`) is not exposed yet; there is no automated health check for DoH (`/dns-query`).
- No `fabricctl` command for people: they are added in the web UI (People) or with Windows' own tools (RSAT) on the
  domain.
- Samba AD (2026-10-05): saving ADMX templates still
  runs `samba-tool ntacl sysvolreset`, which fails at a site's DC (it lacks other sites' GPO folders until S8.4's
  pull brings them); an RODC's password cache is not preloaded; the temporary join account is a Domain Admin
  (whether less is enough is not established); two parents handing out id blocks while cut off from each other
  could pick the same block, and nothing detects it yet (1.6.3.9). A DC that has just joined refuses new accounts
  until the root's RID master has given it a pool (its first request can fail and is retried within minutes): the
  web UI says "not permitted for this site" meanwhile, which misleads.
- A published image whose sources changed is not detected: the lock keeps pinning the old build until someone marks
  it `pending` (the web UI's was found stale by the sandbox, 5.8.1.27); the lock should record each image's context
  hash and the `images` suite refuse a change without `pending`.
- Offline image bundles (`fabricctl images export/import`) are designed but not built (2.6.1, D45). The signed image
  channel was superseded by publishing fabric's own images (D41, built: 2.6.3, 4.7.1).
- No scheduled certificate renewal, monitoring or alerting — service certificates are renewed by `fabricctl setup`
  or `fabricctl certs`.

## 5.4.2.2 Documentation gaps

- IPv6: zones can hold AAAA records (with ULA reverse zones), but `fabric_net` and the published ports are IPv4
  only; this is not described in one place.
