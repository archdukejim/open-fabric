## 5.7.2.1 Two machines per house

The owner runs fabric at home, with a split by load and exposure:

- a **core** Raspberry Pi runs fabric: Keycloak with Postgres, the directory, BIND, Step-CA, OpenBao and the web
  UI. Owner, 2026-10-04: production moves to the **8 GB** Pi; the 4 GB Pi becomes the test Pi (5.7.1.4). The
  smallest supported target stays 4 GB (D31): production having more memory changes nothing in the design;
- an **edge** Raspberry Pi is the only machine with ports open to the internet: a reverse proxy publishing a
  media server with public certificates, a WireGuard endpoint, and a dynamic-DNS client keeping the home address
  current at the public DNS provider (Cloudflare). The home address is dynamic.

The edge machine and its WireGuard are another stack, outside fabric (D92). Let's Encrypt through Cloudflare's
DNS-01 is its own fabric milestone (D78).

## 5.7.2.2 Several houses

Several houses, each its own routed subnet (not one stretched VLAN), linked by WireGuard (another stack, D92);
fabric federates over the tunnels (1.8). Planned (owner, 2026-10-04): five sites — the home LAN (the root) and the
home lab as two separate sites, and three remote family sites with read-only DCs; every site with the full
stack (D91). This is the owner's deployment and a realistic test of fabric, not part of fabric's design.

## 5.7.2.3 What stays out of this repository

The repository is public. Addresses, domain names and accounts of the owner's machines are kept out of it (owner
decision 2026-10-03); they live in the owner's own notes, and an agent asks for them when a task needs them.
