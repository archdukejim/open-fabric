## 5.7.1.2 Docker in WSL

What running the suites there has taught (2026-10-02 to 10-03):

- Call WSL with `MSYS_NO_PATHCONV=1` from Git Bash, and put any multi-line command in a script file: inline
  `bash -c` strings lose their escapes, and a `$(…)` in them is expanded on the Windows side.
- The distribution shuts down a few seconds after its last session ends, stopping detached containers (the
  sandbox exits 255) and restarting the owner's: keep a session open for the whole run.
- Never start a second `tests/run-all.sh` with the same `FABRIC_TEST_OUT` while one runs: run-all clears that
  folder. The dirsrv, keycloak and hardening suites need `render` in the same run.
- Never edit a test script while it runs: bash reads scripts as it goes.
- The WSL kernel can hang: processes stuck in `sync()` (state D on `super_lock`) never exit, 389-DS reports
  "already running as process N" and Docker cannot stop containers. Only `wsl --shutdown` clears it, which stops
  every distribution: ask the owner first.
- A Windows `git worktree` cannot be used from WSL (its `.git` file holds a Windows path): clone inside WSL.
- From Git Bash, Python defaults to the cp1252 code page: set `PYTHONUTF8=1` before it edits UTF-8 files.

## 5.7.1.3 The Windows lab hosts

Waiting to be rebuilt (5.4.1.2). What is pending when they are back: a zone transfer from the Pi's root site to the
lab site on BIND's port 5053; on both hosts Windows Internet Connection Sharing holds UDP 53, and WSL's mirrored
networking needs Hyper-V firewall rules; the Pi's root site still records the old `lab` site as a child — remove
or re-parent it when the lab is rebuilt. Ask the owner before changing Windows firewall or sharing settings.

## 5.7.1.4 The test Raspberry Pi

Reached over SSH with a key only (never a password); it is on the owner's live LAN, so DHCP (`install_kea`) is
never turned on there. Its address and account are kept out of this public repository.

## 5.7.1.5 The agent's test platform

Owner, 2026-10-04: host-1 (Windows, with WSL) and host-2 (Windows) and the test Raspberry Pi are the agent's to
test on as it needs — joining them to the domain and removing them included; breaking them is acceptable. They
answer the checks only Windows can (a Windows join, Group Policy such as the root-CA trust, per-site log-on rights:
spike Q13, Q16; S5) and the multi-site tests. The owner may later rebuild the lab hosts (e.g. as Proxmox servers);
that changes nothing for fabric. How the agent reaches them is asked of the owner; addresses and credentials stay out
of the repository and off command lines.
