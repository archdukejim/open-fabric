## 5.8.3.1 Why

The global rules changed on 2026-10-07 (engineering-rules `d276cda`, `0f4a453`): Volume 5 holds the decisions
(5.1), troubleshooting (5.2) and notes (5.3); Volumes 3, 4 and 5 follow Volume 1's chapters, so one number leads to a
part's design, operation, installation, decisions, troubleshooting and notes (Rule 5.9); a decision's identity is its
topic number (Rule 13). A manual written before may be renumbered once (Rule 5.10). The owner agreed to the
re-baseline and to the subchapter and topic layout of the decisions (2026-10-07).

## 5.8.3.3 How the other volumes follow it

- **Volume 3 (operating):** `3.C` operates what `1.C` designs. Today's 15 chapters fold into the spine: 3.1
  (fabricctl) → 3.3, DNS → 3.4, certificates → 3.5, people, the directory and joins → 3.6, OpenBao → 3.7, the web UI
  → 3.8, federation → 3.9, DHCP → 3.10, 802.1X → 3.11, the DNS filter → 3.12, time → 3.13, images → 3.14, logs → 3.15;
  lifecycle and ports → 3.2. 3.1, 3.16 and 3.17 are stubs.
- **Volume 4 (installing, upgrading, building):** installation, reinstall and restore → 4.2 (the host) and 4.3
  (setup); joining an existing fabric → 4.9; the subordinate CA → 4.5; disk encryption → 4.16; images, packaging,
  testing and development → 4.1 (how fabric is built and released) and 4.14; the rest are stubs.
- **Volume 5:** 5.1 decisions (5.1.C per chapter, one decision per topic); 5.2 troubleshooting (today's 5.6 → 5.2.6
  and 5.2.8); 5.3 notes — 5.3.1 the re-baseline's tables, and every other note under the chapter it concerns
  (alignment history, the stale-code register, review findings, blockers, reasoning, environments, the design
  proposals such as Samba replacing 389-DS → 5.3.6 and 5.3.9, sign-in → 5.3.6).

The full file-by-file table (about 110 files) is produced once the spine is agreed.

## 5.8.3.4 The decisions

About 120 decisions today, in seven files and three numbering schemes (D1–D121, F1–F10, J1–J3, S1–S6). Each becomes a
topic `5.1.C.T` under the chapter it shapes most, written out with: the decision, the chapters it shapes, its date and
who made it, its reasoning (from today's register rows and Volume 5's reasoning), and its status (in force, revised
by, replaced by, removed — the history today's rows carry as "Revised 2026-10-05 …"). Then every reference across the
repository is replaced (whole IDs only: `D13`, never inside `D113`; ranges such as "D106–D111" written out), the old
register deleted, and a D/F/J/S-number-to-topic table kept in 5.3.1 for old commits.

## 5.8.3.5 Impact assessment

- **Architecture:** none. Documents only; no behaviour changes.
- **Breaking changes:** every manual number in Volumes 1, 3, 4 and 5 changes, once. Things that cite them change in
  the same change: links inside the manual; `manual X.Y` references in code docstrings, comments, templates and
  messages printed to users; the tests that check the manual (the docs suite, the function reference generator and
  its number file, the review ledger); `AGENTS.md`. Old numbers stay in git history; 5.3.1's tables resolve them.
  Volume 2 keeps its numbers.
- **Scope creep risk:** large but mechanical. The risk is losing or misplacing content. Guarded by Rule 9's baseline:
  before and after, every old item is accounted for (a new place, or a removal note), every link resolves, the docs
  and lint suites pass, and no code behaviour changes (the code changes are comment and message text only; the unit
  and render suites run before and after).
- **Effort:** the largest documentation change so far — a full day of work or more, done on its own branch
  (`manual-rebaseline`) and merged after 0.6.2 so production does not wait on it.

## 5.8.3.6 How it is done

1. The spine agreed (5.8.3.7), then the full mapping table written into 5.3.1 for review.
2. Volume 1 restructured to the spine; Volumes 3, 4 and 5 moved into their aligned places, stubs where nothing
   exists.
3. Each decision written at its topic, with date, reason and status.
4. Every reference replaced (manual numbers and decision IDs), the old register deleted.
5. The baseline check: every old file and topic mapped, links resolve, the suites pass.
6. One pull request, reviewed by the owner.

## 5.8.3.7 For the owner to decide

1. The spine in 5.8.3.2 — seventeen chapters, one per part of fabric, with Volume 2 kept as it is.
2. Whether a part's design moves from Volume 2 into its Volume 1 chapter (one place to read a part), or Volume 1's
   chapter stays short and points to Volume 2 (less moved, two places to read).
