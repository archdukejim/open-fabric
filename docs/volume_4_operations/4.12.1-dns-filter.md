## 4.12.1.2 The DNS filter: the BIND resolver

Setup turns it on unless you say otherwise (`dns_filter: none`, or *Advanced* on setup's plan; design
[1.12.2](../volume_1_description_and_architecture/1.12.2-bind-resolver.md#11221-status)): a second BIND answers the
network's DNS on `host_ip:53` and BIND moves to port 5053 (`bind_dns_port`), where RFC2136 clients and linked
federation sites find it; fabric's names are never filtered. DHCP hands out the host's address as before.

**Upgrading from 0.6 (AdGuard Home):** run `sudo fabricctl setup` after the upgrade. It moves AdGuard's lists, rules
and upstreams, lists what it could not move (also kept in `/opt/fabric/config/dns-filter-import-<time>.json`), and
removes AdGuard Home from the host (1.12.2.12).

- **Lists, rules and upstreams** are settings ([1.1.9.9](../volume_1_description_and_architecture/1.1.9-optional-parts.md#1199-dns-filter-the-bind-resolver)):
  `dns_filter_lists` (`{name, url}`; the AdGuard DNS filter by default), `dns_filter_allow` and `dns_filter_block`
  (each name with every name below it), `dns_filter_upstreams` (Cloudflare over DNS-over-TLS by default). Change
  them, then apply (`sudo fabricctl --apply`): the running resolver reloads, nothing restarts.
- **`sudo fabricctl dns-filter status`**: whether the resolver answers, and for each list when it was fetched, its
  last good copy, the rules converted and skipped (rules a response policy zone cannot express) and the memory it
  takes. Exit 1 while a list has no good copy.
- **`sudo fabricctl dns-filter lists`**: fetch every list now; only the lists that changed are reloaded. The
  `fabric-dns-lists` timer does the same every night; a list that cannot be fetched keeps its last good copy.
- **Why was a name blocked?** `<base>/resolver/log/rpz.log` names the client, the name and the zone that matched:
  `owner.rpz` (your rules) or `<id>.list.rpz`, one of the lists (`<id>` comes from its URL: 1.12.2.6; the web console will name the
  list, step 5 of 0.7).
- Memory: the default list takes about 190 MiB of the resolver's 384 MiB (`resolver_mem_limit`); the status shows
  what each list takes.
