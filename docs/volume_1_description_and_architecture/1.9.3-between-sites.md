## 1.9.3.1 Between sites: upstream/downstream

> The directory between sites is [1.9.8](1.9.8-federation-on-ad.md) (approved design, build step S8). 389-DS and its
> replication (1.9.3.2) went in S7 (0.5.0, 2026-10-05): until S8, joining shares no directory between sites.

| Service | Federation |
|---|---|
| **Directory (Samba AD)** | Each site runs its own DC. From S8 every site is an OU of one AD domain, replicated by AD between the sites' DCs ([1.9.8](1.9.8-federation-on-ad.md)); until then each site's directory stands alone |
| **Sign-in (Keycloak)** | Each site runs its own Keycloak, federating its **own** DC — sign-in works while the upstream is unreachable. Realm settings come from the same code (`keycloak_bootstrap`) everywhere. TOTP enrolment is per site (see decision F2) |
| **RBAC** | Bundle groups are directory groups (shared between sites from S8). A group applies **everywhere** (`network-operators`) or only to **one site** (`branch1-network-operators`); a site's Keycloak maps global groups and its own site's groups only (decision F4) |
| **PKI** | The root site's CA signs each downstream site's **intermediate** (path length 0 unless the site may hold nested sites, [1.9.5.1](1.9.5-attachment.md#1951-attachment-flat-through-a-node-or-nested); optionally name-constrained to the site's DNS sub-zone, decision F6). Every site trusts the same root: a device certificate from any site is valid everywhere (EAP-TLS roaming, decision F3) |
| **DNS** | The root site owns `<domain>`. Each site serves a **delegated sub-zone** `<site>.<domain>` (NS + glue in the upstream zone), and its DHCP names under `dhcp.<site>.<domain>`. Each side is a **secondary** of the other's zones (TSIG), so names resolve both ways while the link is down |
| **DHCP** | Per site only: a site's subnets are its own; nothing is shared across sites. Upstream sees them read-only |
| **802.1X** | Per site: switches ask their own site; decisions come from the site's own DC. No RADIUS proxying between sites (roaming devices: decision F3) |
| **OpenBao** | Per site: every site keeps its own secrets and unlock methods; nothing replicates between sites. (Optional later: a site's encrypted export deposited upstream for disaster recovery) |
| **Images and packages** | Later (with 2.1.14.1/2.1.14.3): a site pulls the validated image list and images through its upstream, which gives branches an offline path |

## 1.9.3.3 Offline behaviour of a branch (and of every site if the root goes away)

Every site runs everything it needs itself, so with its upstream (or the
root site, or a relay) gone, a site keeps: sign-in for people (Keycloak on
its own DC), DNS for its own zone and (from its
secondary copy) the organisation's zone, DHCP, 802.1X, its web UI, its
secrets (OpenBao), and issuing certificates from its intermediate. Nested
sites below it keep working too.

What waits for the upstream: new sites joining through it; renewing the
site's own CA; revocations from elsewhere. The directory between sites
(S8): [1.9.8.7](1.9.8-federation-on-ad.md#1987-offline-behaviour). A site's CA outlives outages comfortably (default three years,
renewed well before expiry); a site whose parent is gone for good is
re-parented ([1.9.5.1](1.9.5-attachment.md#1951-attachment-flat-through-a-node-or-nested)).
