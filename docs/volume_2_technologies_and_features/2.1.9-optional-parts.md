## 2.1.9.1 Log forwarding (optional)
| Variable | Default | Notes |
|---|---|---|
| `install_fluentbit` | `false` | Fluent Bit forwards the journal and OpenBao's audit log (operations.md → Log forwarding) |
| `log_forwarding` | `{}` | `syslog: {host, port 6514, tls true, ca_file}`, `elastic: {url, user, index, ca_file}`, `hosts: {name: address}`, `buffer_limit: 256M` |
| `ip_fluentbit` | `10.255.0.95` | On fabric_net (metrics for `fabricctl logs status`) |
| `fluentbit_mem_limit` | `64m` | Container memory limit |

The Elasticsearch password is not a setting: `sudo fabricctl logs set-password elastic` keeps it in OpenBao.

## 2.1.9.2 DNS filter (AdGuard Home, on by default)
Design [dns-filter.md](2.4.1-adguard.md#2411-status); operations.md → DNS filter.

| Variable | Default | Notes |
|---|---|---|
| `dns_filter` | `adguard` (D112) | `adguard`: AdGuard Home answers clients on `host_ip:53` and BIND moves to `bind_dns_port` 5053; `none` turns it off. A first deploy starts with Cloudflare and AdGuard's DNS filter; afterwards upstreams, bootstrap servers and lists are set in its UI after signing in |
| `install_adguard` | computed | `dns_filter == adguard` (cannot be set) |
| `hostname_adguard` | `adguard.<domain>` | AdGuard's UI: OIDC sign-in first (permission `dns:filter`); `cname_adguard` (default `adguard`) changes the first label |
| `adguard_upstreams` | `[https://1.1.1.1/dns-query, https://1.0.0.1/dns-query]` (Cloudflare) | Prefills a first deploy only; `[]` = local DNS only (this site's BIND); afterwards upstreams are AdGuard's UI's (fabric keeps only its `[/<zone>/]<ip_bind9>` lines) |
| `adguard_filter_lists` | AdGuard DNS filter | Prefills a first deploy only: `[{name, url}]`; `[]` = none |
| `adguard_rules` | `[]` | Your rules, after the generated `@@\|\|<zone>^$important` ones (fabric's names are never blocked); rules added in the UI are kept below them |
| `ip_adguard` / `ip_oauth2proxy` | `10.255.0.31` / `10.255.0.32` | On fabric_net |
| `adguard_mem_limit` | `256m` | Container memory limit |

## 2.1.9.4 Time (NTP)
Design [ntp.md](2.5.1-chrony.md#2511-status); operations.md → Time. chrony on the host.

| Variable | Default | Notes |
|---|---|---|
| `ntp_servers` | `["time.cloudflare.com nts", "nts.netnod.se nts", "ptbtime1.ptb.de nts"]` (three independent sources: chrony outvotes one that is wrong) | `"<host> [nts] [pool] [prefer]"` (nts: authenticated time). A federated site asks its upstream site first. `[]`: the upstream site only, or this host's own clock |
| `ntp_serve` | `true` | Answer the network (`lan_cidr`, `security.firewall_allow`, the DHCP subnets) on UDP 123; `ntp.<domain>`; Kea hands it out (option 42) |
| `ntp_set_clock` | `true` | `false`: chrony keeps time but never sets the clock (a container sharing its host's kernel clock) |
| `hostname_ntp` | `ntp.<domain>` | Clients' name for the time server, a CNAME to the host (not added when you have a record of that name); `cname_ntp` (default `ntp`) changes the first label |
| `dhcp.ntp` | `[host_ip]` | Time servers Kea hands out (IPv4); `[]` hands out none |

## 2.1.9.5 802.1X (optional)
| Variable | Default | Notes |
|---|---|---|
| `install_freeradius` | `false` | FreeRADIUS 3.2: EAP-TLS, MAB, EAP-TTLS and PEAP decided from the domain (3.5.1) |
| `radius_clients` | `[]` | `[{name, address (IP or network), message_authenticator (true)}]`; overlapping addresses refused |
| `radius_people` | `network-staff` (priority 50), `network-guests` (100), no VLANs | Groups whose members may join by password (EAP-TTLS): `[{group, vlan (optional), priority (100; lower wins)}]`. `[]`: no password logins (stays empty) |
| `hostname_radius` | `radius.<domain>` | Name on the EAP-TLS server certificate (`cname_radius` changes the first label) |
| `ip_freeradius` | `10.255.0.98` | On fabric_net (reaches the DC at `host_ip`) |
| `freeradius_mem_limit` | `128m` | Container memory limit |

Shared secrets are not settings: they live in OpenBao (`radius_secrets`); `fabricctl radius add-client` / `rotate-secret` show them once.

## 2.1.9.6 DHCP (optional)
| Variable | Default | Notes |
|---|---|---|
| `install_kea` | `false` | Kea 3.0 LTS serves DHCP (operations.md → DHCP) |
| `dhcp.interfaces` | — | Host interface(s) to serve, e.g. `[eth0]`; UDP 67 is opened on them only |
| `dhcp.subnets` | — | `[{subnet, id, name, vlan, notes, pools: ["a - b"], routers, options, reservations: [{mac, ip, hostname, options}]}]`; `id` is Kea's subnet id (stored by fabric on the first change; leases are tied to it), `name` one label unique per site, `vlan` 1–4094 unique (a record only), `notes` up to 500 characters, `allow_overlap` why it may overlap another site's network (federation's address plan, up to 200 characters); no subnet may overlap `fabric_subnet`; pools do not overlap; reservations inside the subnet, outside its pools |
| `dhcp.options` | `[]` | Options for every subnet: `{name \| code, data, space, csv_format, always_send}`; one named like fabric's own (`domain-name-servers`, `ntp-servers`, `domain-name`, `domain-search`) replaces it |
| `dhcp.option_defs` | `[]` | `{name, code, type, space, array, record_types}`: options Kea has no name for |
| `dhcp.client_classes` | `[]` | `{name, test (Kea expression), options, next_server, server_hostname, boot_file_name}` |
| `dhcp.lease_time` | `86400` | Seconds, 300 to 2592000 |
| `dhcp.dns` | `[host_ip]` | DNS servers handed to clients |
| `dhcp.domain` | `domain` | Domain name handed to clients |
| `dhcp.ddns` | `true` | Register client hostnames in DNS |
| `dhcp.ddns_subdomain` | `dhcp` | The dynamic zone is `<ddns_subdomain>.<domain>` |
| `ip_kea_ddns` | `10.255.0.97` | kea-dhcp-ddns on fabric_net (sends the updates to BIND) |
| `kea_mem_limit` | `128m` | Memory limit per Kea container |

The DDNS key's secret is generated (`kea_ddns_secret`, in OpenBao); it is not a setting.

## 2.1.9.8 The directory (Samba AD, required)
Design [2.11.2](2.11.2-samba-dc.md#21121-status) and [1.6.3](../volume_1_systems_and_services/1.6.3-samba-directory.md#1631-status).
Every install runs a Samba AD domain controller on the host's address (host network, D98), Windows machines or not;
setup asks the domain and the password policy when they are not set, and an unattended setup refuses without them.

| Variable | Default | Notes |
|---|---|---|
| `ad_domain` | none: **required** | The AD domain, chosen once on the first node and permanent (D87). Suggested: a sibling of fabric's domain at the top of the organisation's name (`lan.example.org` → `ad.example.org`); fabric's own domain or a parent of it is refused (same-domain mode was dropped) |
| *(examples)* | | With fabric's domain `lan.example.org`: `ad.example.org` (the suggestion, beside it) and `ad.lan.example.org` (inside it) work; `lan.example.org` (fabric's own) and `example.org` (a parent of it) are refused. BIND serves the AD zone either way, and the DNS filter forwards it |
| `ad_realm`, `ad_base_dn` | computed | The Kerberos realm (`ad_domain` upper-cased) and the base DN (`DC=` per label); cannot be set |
| `ad_netbios` | the domain's first label | The NetBIOS domain name, at most 15 characters, upper-cased; fixed after provisioning |
| `hostname_dc` | `<hostname>.<ad_domain>` | The DC's name: the host's own name in AD's domain (computed) |
| `ad_password_policy` | none: **required** | The domain's password policy (D89), every key: `minimum_length` (0–64), `complexity` (true/false), `history`, `minimum_age_days`, `maximum_age_days` (0: never), `lockout_threshold` (0: never), `lockout_minutes`, `lockout_window_minutes` |
| `ad_old_password_minutes` | `0` | How long AD accepts a previous password for network sign-ins after a change (D93; AD's own default is 60) |
| `ad_dc_type` | `writable` | A site's DC: `writable` or `rodc` (read-only); from the invitation (`--dc`). The root's is always writable |
| `ad_join_server`, `ad_join_server_name` | `''` | A joining site: the root DC's address and name, from the join's answer (setup writes them) |
| `posix_id_range` | `''` | A joining site: its uid/gid block from its parent, `first-last` (D97); empty at the root |
| `ad_site_ou` | `OU=<site_name>,OU=sites` | Where this site's OU sits below `ad_base_dn`: in its parent's (D105, 1.8.8.14); a joining site gets it from the join |
| `ad_org_ou` | `OU=organisation,` + `ad_site_ou` | The organisation's OU below `ad_base_dn` (in the root site's OU); a joining site gets it from the join |
| `ad_ntp_signd_dir` | `/var/lib/samba/ntp_signd` | Where the DC's time-signing socket is shared with the host's chrony, which signs Windows members' time (D100); the one folder Ubuntu's AppArmor profile lets chronyd use |
| `ad_rpc_ports` | `49152-49251` | The DC's RPC port range (narrowed from AD's 49152–65535), opened in the firewall |
| `posix_id_block` | `100000` | uid/gid numbers handed to each site (D97) |
| `samba_mem_limit` | `512m` × `host_ram_capacity` ÷ 4 | Container memory limit |
