## 3.15.4.1 What fabric sets by itself

fabric keeps three policies of its own for every site and rewrites them on each apply: the trust in fabric's root
CA, the site's log-on rights and its Windows baseline (3.15.3.1). Leave those alone; everything else is yours, in the
site's `fabric: <site> admin settings` policy, which fabric never touches except through the commands below (design:
[2.11.2.9](../volume_2_technologies_and_features/2.11.2-samba-dc.md#21129-group-policy-and-the-admx-editor)). Windows'
own tools (RSAT's Group Policy editor) work on the same domain too.

## 3.15.4.2 Loading templates

Policies come from ADMX templates. fabric does not ship Microsoft's (its licence does not allow it): download the
*Administrative Templates (.admx)* for your Windows version from Microsoft, then load the folder that holds the
`.admx` files and their `en-US` language folder:

```bash
sudo fabricctl gpo load /path/to/PolicyDefinitions
```

```bash
sudo fabricctl gpo templates
```

They go into the domain's central store, where Windows' own editor finds them as well.

## 3.15.4.3 Finding and setting policies

```bash
sudo fabricctl gpo list "screen saver"
```

lists the matching policies with their names, whether they are for machines or people, and their elements (the
values a policy takes: `text:…`, `decimal:…`, `boolean:…`, `enum:…`, `list:…`). Then:

```bash
sudo fabricctl gpo set <policy> <element>=<value>
```

- a number for `decimal`, any text for `text`, `on` or `off` for `boolean`, an option's name or number for `enum`,
  and `a;b;c` for `list`;
- `--disabled` sets the policy to *Disabled* instead;
- `sudo fabricctl gpo clear <policy>` puts it back to *Not configured*;
- `sudo fabricctl gpo show` lists everything the site's admin settings policy sets.

Machine policies reach the site's machines at their next policy refresh (`gpupdate`, or within about 90 minutes);
people's policies at their next log-on. Every change is in the audit log.

## 3.15.4.4 Your own templates

For settings of your own (a registry value your software reads), start from fabric's blank template:

```bash
sudo fabricctl gpo starter ~/my-policies
```

Rename the files and the namespace, replace the example policy with yours (each writes under
`Software\Policies\<your organisation>`), then `sudo fabricctl gpo load ~/my-policies`.

## 3.15.4.5 Controls the sites below cannot change

A site nested under yours inherits your `admin settings` as defaults: it may set the same policy differently, or block
inheritance on its OU (1.8.8.14). For a setting the sites below must keep, set it as a **control** instead:

```bash
sudo fabricctl gpo set <policy> <element>=<value> --control
```

It goes into your site's `fabric: <site> controls` policy, which is linked *enforced*: it applies to your site and
every site below it, wins over their own policies and passes their blocked inheritance. `gpo show --control` lists
them and `gpo clear <policy> --control` removes one. In the web UI (Directory, Group Policy) the controls are listed
apart, and a policy is set as one with *As a control (enforced)*.
