## 3.15.2.1 What a joined machine gets

An Ubuntu 24.04 or 26.04 machine joins the domain into its site's machines (design:
[2.10.2](../volume_2_technologies_and_features/2.10.2-linux-join-ad.md)). Afterwards the site's people log on with
their domain password (at the console or over SSH), with the same user and group numbers on every machine; who may
log on is the site's log-on rights, the same as on Windows; `kinit` gives them a Kerberos ticket; their home folder
is made at first logon; and they keep logging on with the password they last used while the domain controller is
away. The machine trusts fabric's CA and takes its time from `ntp.<domain>`.

The installer is on the certificates page, `http://certs.<domain>/`, which also shows the root CA's SHA-256
fingerprint. The installer refuses to go on unless the CA it downloads has exactly that fingerprint, and then
nothing on the machine has changed.

## 3.15.2.2 Joining with a site admin's account

On the machine, as root, with the fingerprint from the certificates page:

```bash
wget -nv http://certs.<domain>/join-linux.sh
```

```bash
sudo bash join-linux.sh <root CA SHA-256> --user <site admin>
```

It asks for the admin's password (it is never taken from the command line). The machine's name is its host name;
`--name <name>` gives another (1–15 letters, digits or dashes). `--site <site>` joins it to another site (nested or not) than the
one whose certificates page served the installer.

## 3.15.2.3 Joining with a one-time join password

So that no admin password is typed on the machine, pre-create it on the fabric host:

```bash
sudo fabricctl domain add-machine <name>
```

This prints a one-time join password once. On the machine:

```bash
sudo bash join-linux.sh <root CA SHA-256> --one-time
```

and give that password when asked. The machine's account is in the site's machines from the start.

## 3.15.2.4 Sudo

Members of the site's admins group (`<site>-admins`) and of the web UI's admin group may run anything with sudo on
the site's machines; nobody else may, unless an admin adds a rule (`sudoRole` entries in the site's `OU=sudoers`,
for example with Windows' RSAT tools until the web UI's domain section comes). On Ubuntu 26.04 the installer makes
the classic `sudo` the default, because the default `sudo-rs` cannot read the domain's rules.

## 3.15.2.5 When it does not work

- *the root CA served is …, not the fingerprint given*: copy the fingerprint again from the certificates page; if it
  still differs, the machine is not talking to your fabric host — do not continue.
- *the join was refused*: a site admin of that site with the right password, or (`--one-time`) a machine
  pre-created with `fabricctl domain add-machine` under the same name and the password it printed. A one-time
  password works once.
- A person cannot log on: they must be a person of the machine's site (or granted it), and have set their own
  password at the web sign-in first; `sudo sssctl user-checks <name>` on the machine shows why.
