## 1.9.1.1 Where security is described

This is the home chapter for security (5.8). The global rules (Rule 10) apply to fabric as they are; this chapter
holds what fabric adds. Each aspect lives in its own volume: the agent's privilege model in 1.5.2 and 1.5.3,
people's access in 1.5.5, secrets in 1.7.1, container hardening in 1.3.4 and 1.3.8, the host changes fabric asks
about in 2.7.1, and the relaxations an install may choose in 1.2.2 (D50). Moved from `AGENTS.md` §4 on
2026-10-03.

## 1.9.1.2 Never weaken silently

Secure by default; every relaxation is an explicit setting, shown in `fabricctl status` and the Open Fabric web
UI (D50).

## 1.9.1.3 Containers and privileges

- Containers: non-root, `cap_drop: ALL` (+ only what is needed, D49), `no-new-privileges`, read-only root where
  possible. Nothing mounts the Docker socket. Nobody is added to the `docker` group.
- Privileged work happens only in `fabric-agent`, through a fixed, validated API — never "run this command"
  (1.5.3).

## 1.9.1.4 Secrets, TLS and images

- Secrets never on a command line (`argv` is world-readable); pass them via files (0400/0600) or environment
  (D47). No hard-coded or shared default passwords.
- TLS everywhere, verified against the fabric root CA — never `verify off` for new code (D51).
- Images are pinned by digest; local builds start `FROM` a pinned digest. An upstream push must never change what
  runs (D40).

## 1.9.1.5 Core services start without OpenBao

Core services (DNS, DHCP, LDAP, SSO, nginx) must never depend on OpenBao to *start*: a sealed or broken vault
must not take the network down with it (1.7.1).
