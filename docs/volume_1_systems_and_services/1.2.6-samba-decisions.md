## 1.2.6.1 Decisions for the owner

| # | Question | Proposal |
|---|---|---|
| S1 | **Where passwords live** | 389-DS stays the source of truth; passwords reach Samba when set (fabric functions, a Keycloak mapper, Samba's syncpasswords back). Alternatives: (b) AD becomes the source of people and passwords and Keycloak federates to AD — simpler password flow, but fabric's directory would follow AD and the M5 design changes; (c) 389-DS's Windows-sync plugin — legacy, unproven with Samba |
| S2 | Site DCs | Read-only DCs if S0 proves them; else full DCs |
| S3 | The DC's address | Its own LAN address (macvlan) — not a host change; the host's firewall does not cover it (shown as a relaxation) |
| S4 | Linux joins | AD (`realm join`), with sudo rules kept in 389-DS |
| S5 | Default GPOs | Time, 802.1X profile, fabric's root CA; nothing else unless asked |
| S6 | Let's Encrypt through Cloudflare | Its own design after this one ([2.11.1.13](../volume_2_technologies_and_features/2.11.1-samba-ad.md#211113-related-separate-designs-after-this-one)) unless pulled forward: it is single-host and testable now |
