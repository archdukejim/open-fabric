# 1.11.1 About the function reference

Topics:
- 1.11.1.1 What it is
- 1.11.1.2 How it is numbered
- 1.11.1.3 Keeping it current

## 1.11.1.1 What it is

Every function and method in fabric's own code (`fabricctl/lib/`, `webui/`, the shell scripts), generated from
its structured docstring (decision D36): purpose, inputs, returns, failures, what feeds on it, and who calls it
(found in the code). One subchapter per area of the code (1.11.2 onwards); each source file is a topic, each
function a sub-topic. Never edited by hand: change the docstring, then regenerate.

## 1.11.1.2 How it is numbered

Numbers follow 5.7 like every other chapter: they are given once and never reused. A committed registry,
`tests/docs/lib_doc_numbers.tsv`, records the number of every area, file and function the generator has ever
seen. A new one takes the next number after the highest ever used at its level; one that is gone keeps its
number with a `[DELETED]` entry and the date it was found gone. So a function's number stays the same for as long
as the function exists, and a link to it keeps working.

## 1.11.1.3 Keeping it current

`python3 tests/docs/gen_lib_doc.py` regenerates the subchapters, the registry and this chapter's list in the
Volume 1 index; `--check` (part of `tests/run-all.sh docs`) fails when they are not what the code says.
