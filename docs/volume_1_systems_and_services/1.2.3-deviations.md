# 1.2.3 Deviations from the global rules

Topics:
- 1.2.3.1 Tests are integration suites by domain (D59)
- 1.2.3.2 Sign-in starts at a password (D110)

## 1.2.3.1 Tests are integration suites by domain (D59)

- **Rule relaxed:** 7.1, "each source file gets one test file at the mirrored path".
- **What fabric does instead:** tests are organised by domain under `tests/<domain>/` (dns, pki, dirsrv, kea,
  federation, …), each suite proving its domain against real containers, plus the end-to-end sandbox
  (`tests/sandbox/`) and the real-host suite (`tests/host/`).
- **Why:** fabric's behaviour lives in how its functions drive real services (389-DS, BIND, Kea, Keycloak,
  OpenBao). One test file per source file would test each function alone, mostly against mocks, which Rule 9
  restricts to pure logic. Approved by the owner on 2026-10-03.

## 1.2.3.2 Sign-in starts at a password (D110)

- **Rule relaxed:** 10, "secure by default".
- **What fabric does instead (when 5.8.2 is built, after 0.6.0):** a new install signs everyone in, admins
  included, with a username and password. Every stronger layer — TOTP, a passkey, a per-user certificate, the
  web UI's client certificate — is raised from the web console; lowering one is done only at the command line
  (D111), with a typed confirmation, an audit entry and a warning that stays visible.
- **Why:** the owner (2026-10-07): a first standup should be simple, and everything can be raised to a more
  secure method from the web console. The rule's other half still holds: every relaxation below what an
  install has is explicit, and status output and the web UI show it.
