## 1.3.2.1 Repository Structure

The global Rule 7 layout, adopted on 2026-10-03 (5.1.3; it replaced D25's `fabricctl/`, `webui/` and
`installers/` folders):

```text
.
├── src/                  # all code (Rule 7.1)
│   ├── fabriclib/        # domain code, one operation per file (setup/, dns/, dhcp/, radius/, vault/, …)
│   ├── agent/            # fabric-agent: the privileged host API behind the web UI
│   ├── federation/       # fabric-federation: the endpoint sites join through
│   ├── webui/            # Open Fabric, the control-plane web UI (its own container; name kept, D79)
│   ├── ux/
│   │   ├── cli/          # the fabricctl command, manage.sh, deploy.py, interactive.py, keycloak_bootstrap.py
│   │   └── web/          # server.py (starts the web UI), devserver.py (the dev preview)
│   └── containers/       # code that runs inside service containers (389-DS seeding, FreeRADIUS policy)
├── templates/            # one folder per service: config and compose templates (Jinja); vars.yaml.j2;
│   └── webui-app/        #   the web UI's page templates
├── static/               # vendor/ (third-party, THIRD_PARTY_NOTICES), nginx/, webui-app/
├── config/               # VERSION, images.lock.yaml, link-vars-template.yaml
├── examples/             # vars.yaml
├── packaging/
│   ├── deb/              # the Debian package: assemble-tree.sh, build-deb.sh, maintainer scripts
│   └── images/           # one build context per image fabric builds (Dockerfile + what it copies)
├── scripts/              # install-from-checkout.sh; docs/ (the function reference, the review ledger)
├── docs/                 # the manual
└── tests/                # one folder per suite (D59); run-all.sh
```

The package assembles the installed tree from these (`packaging/deb/assemble-tree.sh`, the one place that knows
the mapping): `src/` becomes `/usr/lib/fabricctl/fabric/lib/` (the CLI's scripts and the web UI's entry points
included), `templates/` its `jinja/`, each `packaging/images/<service>/` its `jinja/<service>/build/`, `config/`
its top folder; `fabricctl setup` copies that to `/opt/fabric/`. The installed layout never depends on this one
(D43): it did not change when the repository was split (D25) or moved to this layout. Python packages keep their
names (`fabriclib`, `webui`), so a checkout runs with `src/` on `sys.path`.
