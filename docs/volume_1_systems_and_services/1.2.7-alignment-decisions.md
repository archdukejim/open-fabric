Topics:

## 1.2.7.1 The decisions

Made by the owner on 2026-10-03 while aligning fabric to the global rules (5.1.1); proposals and their impact
assessments in 5.1.3 and 5.1.4.

| ID | Question | Decision |
|---|---|---|
| D79 | Package names in the Rule 7 layout | Kept: `fabriclib` and `webui` stay; the web UI's code is `src/webui/` and `src/ux/web/` holds only the thin entry that starts it; the installed tree does not change (5.1.3) |
| D80 | Published images and custom service-account ids (P1) | Published images carry the default ids (D42); a host whose ids differ builds that one image locally (5.1.4) |
| D81 | Signing published images (P2) | Keyless signing with cosign in GitHub Actions; hosts verify the signature before using a new digest |
| D82 | Building arm64 images (P3) | GitHub's native arm64 runners, no emulation |
| D83 | Visibility of published images (P4) | Public on the GitHub Container Registry, like the repository |
| D84 | Which refs publish images | An exception for this repository: main and `rc/<version>` branches publish by hand (`<version>`, `<version>-rc.<run>`); a `v<version>` tag publishes `<version>` by promoting the digests its lock pins, after verifying them (2.6.3.6) |
| D85 | A signature that cannot be verified (offline, air-gapped) | Refused: the new digest is not used. `image_signature_check: false` turns the check off, and `fabricctl status` and the web UI show it while off (2.6.3.4) |
| D86 | How hosts run cosign | The official cosign image, pinned by digest in `images.lock.yaml` and run with Docker; nothing installed on the host (2.6.3.2) |

D84–D86 were decided on 2026-10-03 while designing step 7b; their reasoning is in 5.1.4.5.

The next new decision is D91 (D87–D90: 1.2.6).
